## Context

窗格移动候选由 `AppState` 统一生成，输入和渲染都按同一顺序消费。当前每个可移动窗格先产生四个边缘目标，所有工作区的新标签页目标和新工作区目标最后追加；覆盖层却只显示最多十行。目标标签渲染只读取目标 ID，没有使用已经缓存于 `AppState` 的工作区、标签页和终端标题。

## Goals / Non-Goals

**Goals:**

- 多分屏下无需滚动即可选择脱离为新标签页或新工作区。
- 移动目标在有限宽度内优先展示用户可识别名称，同时保留稳定窗格编号用于消歧。
- 键盘循环、鼠标点击和提交继续消费同一候选顺序。

**Non-Goals:**

- 不改变 pane move API、提交语义或失败回滚。
- 不新增候选滚动状态，也不重做分屏预览交互。

## Decisions

### 1. 在候选生成源头将脱离目标置顶

先生成各工作区的新标签页目标和新工作区目标，再生成窗格边缘移动目标。这样输入、命中测试和渲染天然保持一致，脱离目标始终位于最多十行的首屏内。仅在 UI 层重排会造成键盘顺序与显示顺序不一致，因此不采用。

### 2. 渲染时从稳定目标标识解析展示上下文

目标标签使用“工作区名称 / 标签页名称 / 窗格标题或稳定编号 · 方向”。工作区与标签页名称读取现有缓存，窗格标题复用终端边框标题优先级；无标题或标题重复时始终附带公开 pane ID。候选状态仍只保存稳定标识，不把易变展示文本写入交互状态。

## Risks / Trade-offs

- [风险] 名称较长时会被面板宽度裁剪 → 将最关键的层级信息前置并保留末端稳定 pane ID，测试覆盖短名称和重名场景。
- [风险] 初始选中项从移动目标变为新标签页 → 这是“移动或脱离”入口的安全可达性取舍；提交仍需用户明确点击或按 Enter。

## Migration Plan

无需数据迁移。若回归失败，回退候选排序和纯展示标签即可，不影响已移动窗格或持久化会话。
